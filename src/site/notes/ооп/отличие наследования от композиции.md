# Отличие наследования от композиции
---
dg-publish: true
---

При разработке программ в ООП стиле важно понимать различие между **наследованием** и **композицией**.

Подумайте над следующими примерами:

- Класс "Млекопитающие" - это что-то большее, нежели, чем "Слон".
- "Университет" больше, чем "Деканат".
- "Страна" больше, чем "Область".
- Понятие "Вычислительное устройство" более общее, чем "Ноутбук".

Есть принципиальная разница в отношении между сущностями в приведенных примерах.

К первой группе можно отнести наборы, в которых отношение можно выразить словом "является", "Слон" является "Млекопитающим", "Ноутбук" является "Вычислительным устройством". Ко второй группе относятся понятия, в которых отношение выражается словами "имеет", "состоит" или "входит": "Страна" состоит из "Областей", "Деканат" входит в "Университет".

Если для указания отношения между сущностями мы можем использовать слово "является", то для его программной реализации применяется **наследование**, если слова "имеет", "состоит" или "входит", то **композицию**. **Композиция** - это отношение типа _целое-части_.

Реализуем наследование для фигуры и окружности:

```cs
class Shape
{
    public int Color { get; set; }
}

class Circle: Shape
{
    public double Center { get; set; }
    public double Radius { get; set; }
}
```

Пример композиции между классами "Комната" и "Стена":

```cs
class Wall
{
    public double Height { get; set; }
    public double Width  { get; set; }
}

class Room
{
    public Wall NorthWall { get; set; }
    public Wall SouthWall { get; set; }
    public Wall WestWall { get; set; }
    public Wall EastWall { get; set; }
}
```

Q: Какое отношение между классами реализуется через наследование?
A: Отношение "является" (например, "Слон" является "Млекопитающим").
W1: Отношение "имеет" (например, "Страна" имеет "Области").
W2: Отношение "состоит из" (например, "Комната" состоит из "Стен").
W3: Отношение "входит в" (например, "Деканат" входит в "Университет").
---

Q: Какой принцип ООП демонстрирует композиция?
A: Отношение "целое-части" (например, "Университет" включает "Деканат").
W1: Наследование свойств от родительского класса (например, "Ноутбук" наследует от "Вычислительного устройства").
W2: Абстракция общих характеристик (например, "Млекопитающие" объединяют общие признаки).
W3: Полиморфизм методов (например, переопределение метода в дочернем классе).
---

Q: В каком случае используется композиция вместо наследования?
A: Когда отношение между объектами выражается словами "имеет" или "состоит из".
W1: Когда один класс является частным случаем другого (например, "Круг" — частный случай "Фигуры").
W2: Когда нужно переопределить метод родительского класса в дочернем.
W3: Когда классы связаны отношением "является" (например, "Собака" является "Животным").
---

Q: Какой пример иллюстрирует наследование в ООП?
A: Класс "Circle" наследует свойства от класса "Shape".
W1: Класс "Room" содержит объекты класса "Wall".
W2: Класс "Country" управляет списком объектов "Region".
W3: Класс "Car" агрегирует объекты класса "Engine".
---

Q: Что означает отношение "является" в контексте ООП?
A: Возможность реализации через механизм наследования.
W1: Возможность хранения одного объекта внутри другого.
W2: Возможность разделения общего интерфейса между классами.
W3: Возможность динамического изменения поведения объекта во время выполнения.
---

Q: Какая связь между классами характерна для композиции?
A: Один класс содержит экземпляры другого класса как свои части.
W1: Один класс наследует поля и методы другого класса.
W2: Один класс реализует интерфейс другого класса.
W3: Один класс переопределяет методы другого класса.
---

Q: Какой пример НЕ относится к наследованию?
A: Класс "Room" содержит объекты класса "Wall".
W1: Класс "Lion" наследует от класса "Animal".
W2: Класс "Smartphone" наследует от класса "Device".
W3: Класс "Square" наследует от класса "Shape".
---

Q: В чем ключевое отличие композиции от наследования?
A: Композиция описывает отношение "целое-части", а наследование — "является".
W1: Композиция позволяет переиспользовать код, а наследование — нет.
W2: Наследование создает независимые объекты, а композиция — зависимые.
W3: Композиция работает только с интерфейсами, а наследование — с классами.
---

Q: Какой из примеров демонстрирует композицию?
A: Класс "University" содержит объект класса "Faculty".
W1: Класс "Bird" наследует от класса "FlyingCreature".
W2: Класс "Rectangle" наследует от класса "Polygon".
W3: Класс "Car" наследует от класса "Vehicle".
---

Q: Почему в примере с "Room" и "Wall" используется композиция?
A: Потому что "Room" состоит из "Wall" как своих частей.
W1: Потому что "Wall" является частным случаем "Room".
W2: Потому что "Room" наследует свойства "Wall".
W3: Потому что "Wall" реализует интерфейс "Room".
