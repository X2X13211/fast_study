В программировании существует два основных способа переиспользовать уже написанный программный код - это **наследование** и **обобщение**. С наследованием мы с вами познакомились в модуле 5, в рамках данного урока речь пойдет об обобщении.

Идею обобщения проще раскрыть на примере. Посмотрите на пару методов, которые приведены ниже:

```cs
int[] AddValue(int value, int[] arr)
{
    var result = new int[arr.Length];

    for(int i = 0; i < arr.Length; i++)
        result[i] = arr[i] + value;

    return result;
}

int[] Squaring(int[] arr)
{
    var result = new int[arr.Length];

    for (int i = 0; i < arr.Length; i++)
        result[i] = arr[i] * arr[i];

    return result;
}
```

Первый из них принимает на вход массив и число, которое нужно прибавить к каждому элементу массива, а возвращает модифицированный соответствующим образом массив. Второй, принимает массив, элементы которого нужно возвести в квадрат и возвращает массив квадратов чисел. Если мы внимательно посмотрим на содержимое этих методов, то увидим, что структурно они делают одну и ту же работу: создают новый пустой массив, обходят элементы исходного массива, с каждым элементом выполняют определенную операцию, результат кладут в соответствующую ячейку пустого массива, и в конце возвращают массив с результатами вычислений.

Оказывается, что такого типа манипуляция: применение какой-либо функции к каждому элементу массива - это довольно распространенный шаблон работы с наборами данных, и данными не обязательно должны быть числа. В примере ниже приведен метод, который убирает все начальные и конечные символы пробела у строк из заданного массива. Структурно он соответствует приведенным выше методам, оперирующими с числами:

```cs
string[] TrimStrings(string[] arr)
{
    var result = new string[arr.Length];

    for (int i = 0; i < arr.Length; i++)
        result[i] = arr[i].Trim();

    return result;
}
```

Идея обобщения заключается в том, что мы можем написать алгоритм, который потенциально работает с любыми типами данных, а перед использованием указываем тип над экземплярами которого хотим выполнить операцию. Также сюда относятся различные типы хранилищ данных (**контейнеры**): списки, массивы, словари и т.п. При таком подходе один раз реализовав алгоритм или контейнер, мы можем применить его к разным типам данных, в противном случае пришлось бы для каждого типа данных делать свою реализацию.

# Создание обобщенных типов в C#

Для построения типа, который будет обобщенным, необходимо указать у него **параметр типа**. **Параметр типа** указывается после имени типа в угловых скобках:

```cs
class MyGenericClass<T> { }
```

Параметров типа может быть несколько:

```cs
class MyGenericClass<T1, T2, T3> { }
```

Имена параметров типа рекомендуется начинать с заглавной буквы `T`, от слова `Type` - тип.

После указания имени типа, далее, в теле класса (структуры, интерфейса), можно указывать этот тип в качестве типов полей, свойств, аргументов и возвращаемых значений. При объявлении переменной типа необходимо указать явно тип, который будет использоваться.

Дополним `MyGenericClass` свойством `Value`.

```cs
class MyGenericType<T> 
{ 
    public T Value { get; init; }
}
```

Создадим объекты класса `MyGenericType` для хранения значений разных типов.

```cs
var a = new MyGenericType<string>() { Value = "hello" };
var b = new MyGenericType<int>() { Value = 123 };

Console.WriteLine(a.Value); // hello
Console.WriteLine(b.Value); // 123
```

Обобщения доступны для классов, структур, интерфейсов и делегатов, _обобщенные перечисления создавать нельзя_.

# В чем преимущества от использования обобщенных типов

Известно, что все типы в C# являются наследниками от `System.Object`, тогда возникает вопрос: "а зачем нам все эти обобщения, если мы просто можем хранить объекты класса `object`, и, где нужно приводить их к требуемому типу?".

Например, мы бы могли предложить вот такую альтернативу `MyGenericType`:

```cs
class MyNotGenericType
{ 
    public object Value { get; init; }
}
```

Работа с таким классом выглядела бы так:

```cs
var a = new MyNotGenericType() { Value = "hello" };
var b = new MyNotGenericType() { Value = 123 };

Console.WriteLine((string)a.Value); // hello
Console.WriteLine((int)b.Value); // 123
```

На первый взгляд никакой разницы - результата мы добились такого же. Но если изучить этот вопрос более внимательно, разница всё-таки есть.

**Производительность.** Обобщенный код более производительный по сравнению с необобщенным. Особенно это "чувствуется" при работе с коллекциями (массивы, списки и т.п.). Если мы будем работать не с обобщенным вариантом, а с коллекцией, которая хранит объекты типа `object` , то при размещении в ней элементов типов значений, они будут подвергаться постоянной упаковке/распаковке. Интенсивная работа с такой коллекцией приведет к потере производительности.

**Безопасность типов.** Во время компиляции кода выполняется большое количество проверок на предмет того, можно ли выполнять предлагаемые действия над экземплярами конкретных типов. Если этого сделать нельзя, то сборка проекта будет остановлена, и программист увидит соответствующую ошибку. При использовании типа `object` вместо обобщений  часть таких проверок будет выполняться во время исполнения программы, и если приведение типов выполнить будет нельзя, то возникнет исключение. Может случиться так, что при тестировании не все ошибки такого рода будут выявлены и они попадут в готовый продукт.

**Простота кода.** Разработчики чаще читают код, чем пишут. Поэтому, по возможности, нужно снижать умственную нагрузку на программиста, который будет читать ваш код. Если ему приходится думать и держать в голове много информации по поводу того, какой тип на самом деле используется в методе, и можно ли с ним делать то, что вы предлагаете - велика вероятность, что он неправильно поймет какой-то важный момент или пропустит ошибку на код-ревью.

# Обобщенные интерфейсы

Обобщенные интерфейсы очень полезны для построения быстрых и безопасных, с точки зрения типов, решений. Технически обобщенные интерфейсы реализуются так же как классы или структуры.

```cs
interface MyGenericInterface<T>
{
    T DoSomething();
}
```

В стандартной библиотеке довольно много полезных обобщенных интерфейсов, например, `IEquatable<T>`, который предоставляет контракт для сравнения объектов между собой на равенство.

Выглядит он следующим образом:

```cs
public interface IEquatable<T>
{
    bool Equals(T? other);
}
```

Реализуем класс `Person` с поддержкой `IEquatable<T>`:

```cs
class Person : IEquatable<Person>
{ 
    public string Name { get; init; }
    public int Age { get; init; }

    public bool Equals(Person? other)
    {
        if(other == null) 
            return false;

        if(other == this) 
            return true;

        var result = Name == other.Name
            && Age == other.Age;

        return result;
    }
}
```

Приведем несколько примеров работы с `Person`:

```cs
var p1 = new Person() { Name = "John", Age = 21 };
var p2 = p1;
var p3 = new Person() { Name = "John", Age = 21 };
var p4 = new Person() { Name = "Mary", Age = 23 };

Console.WriteLine(p1.Equals(p2)); // True
Console.WriteLine(p1.Equals(p3)); // True
Console.WriteLine(p1.Equals(p4)); // False
Console.WriteLine(p1.Equals(null)); // False
```

Переменные `p1` и `p2` указывают на один и тот же объект в памяти, поэтому по сути они равны. `p1` и `p3` указывают на разные объекты в памяти, но их содержимое одинаково, поэтому результат их сравнения - `true`. В третьей строке сравниваются разные объекты с различным содержанием, в четвертой приводится пример сравнения с `null`.

# Обобщенные методы

Помимо обобщенных типов можно создавать обобщенные методы. Сам тип при этом может не быть обобщенным. Параметр типа указывается после имени метода.

```cs
class MyClass
{
    public void GenericMethod<T>(T input) =>
        Console.WriteLine($"From GenericMethod(): {input}");    
}
```

При вызове метода аргумент типа можно указать, но можно и опустить, тогда система вывода типов в C# определит его самостоятельно.

```cs
var mc = new MyClass();

mc.GenericMethod<int>(123);
mc.GenericMethod<string>("hello");

mc.GenericMethod(123.456);
```

# Ограничения. Часть 1.

Довольно часто возникает ситуация, когда необходимо наложить некоторые ограничения на параметр типа, к примеру чтобы тип поддерживал какой-то интерфейс, содержал конструктор без параметров или был представителем ссылочного (значимого) типа.

Для задания ограничений на параметр типа используется ключевое слово `where`, после которого перечисляются ограничения.

Варианты ограничений, которые можно задать для параметра типа:

- `where T : class`. Тип `T` должен относиться к ссылочным типам.
- `where T : struct`. Тип `T` должен относиться к значимым типам.
- `where T : new()`. Тип `T` должен иметь конструктор "по умолчанию" (без параметров).
- `where T : Интерфейс`. Тип `T` должен реализовать интерфейс `Интерфейс`.
- `where T : Базовый класс`. Тип `T` должен быть наследником класса `Базовый класс`.

Рассмотрим на примерах работу с ограничениями.

Пример работы с `class` и `struct`.

```cs
class GenericClassRef<T> where T: class { }

class GenericClassVal<T> where T : struct { }
```

В качестве аргумента типа класса `GenericClassRef` можно указать любой ссылочный тип, для `GenericClassVal` - значимый тип.

```cs
var gcr1 = new GenericClassRef<string>();
var gcr2 = new GenericClassRef<int>(); // Ошибка! int - это тип-значение

var gcv1 = new GenericClassVal<string>(); // Ошибка! string - это ссылочный тип
var gcv2 = new GenericClassVal<int>(); 
```

Пример работы с `new()`.

```cs
class GenericClassCons<T> where T : new() { }

class MyClass
{
    private readonly int _value;
    public MyClass(int value) => _value = value;
}
```

У класса `GenericClassCons` объявлен параметр типа `T`, который должен иметь конструктор без параметров. Класс `MyClass` содержит только конструктор с параметром.

```cs
var gcc1 = new GenericClassCons<int>();

// Ошибка! У MyClass нет конструктора без параметров
var gcc2 = new GenericClassCons<MyClass>(); 
```

# Ограничения. Часть 2. Интерфейс

Для демонстрации работы с `Интерфейсом` создадим класс `Rating`, который реализует метод `GetBetter`, определяющий первого лучшего представителя среди переданных ему экземпляров. Для сравнения элементов списка используется интерфейс `IComparable<T>`

```cs
class Rating<T> where T : IComparable<T>
{
    public T GetFirstBetter(List<T> list)
    {
        if (list.Count == 0)
            throw new ArgumentException("List is empty");

        T better = list.First();
        for(int i = 1; i < list.Count; i++)
            if (better.CompareTo(list[i]) < 0)
                better = list[i];

        return better; 
    }
}
```

Создадим класс, моделирующий участника соревнований по программированию `Participant`, который содержит два поля: `Name` - имя и `CountOfTasks` - количество решенных задач. Для того чтобы можно было сравнивать участников друг с другом, реализуем интерфейс `IComparable`.

```cs
public class Participant : IComparable<Participant>
{
    public string Name { get; set; } = string.Empty;
    public int CountOfTasks { get; set; }    

    public int CompareTo(Participant? other)
    {
        if (other == null)
            return 1;

        if (CountOfTasks > other.CountOfTasks)
            return 1;
        else if (CountOfTasks == other.CountOfTasks)
            return 0;
        else
            return -1;
    }
}
```

Теперь мы можем использовать `Rating` для определения первого лучшего участника.

```cs
var prs = new List<Participant>()
{
    new Participant() {Name = "John", CountOfTasks = 1},
    new Participant() {Name = "Mike", CountOfTasks = 3},
    new Participant() {Name = "Mary", CountOfTasks = 5},
};

var rating = new Rating<Participant>();
var better = rating.GetFirstBetter(prs); // участник с именем "Mary"
```

# Ограничения. Часть 3. Базовый класс

Для демонстрации ограничения `БазовыйКласс` создадим запись, моделирующую фигуру, которая будет базовой для набора геометрических фигур.

```cs
record Shape(int Color);

record Rectangle(double Height, double Width, int Color) : Shape(Color);
```

Дополнительно создадим запись `Circle` - окружность, которая не является потомком `Shape`.

```cs
record Circle((double X, double Y) Center, double Radius, int Color);
```

Операции с геометрическими фигурами вынесем в отдельный класс `ShapeOperations`.

```cs
class ShapeOperations
{
    public T ChangeColor<T>(T shape, int color)
         where T : Shape =>
        shape with { Color = color };
}
```

Операция `ChangeColor` может быть выполнена над представителями `Shape` и `Rectangle`, но не над `Circle`, т.к. последний не является наследником `Shape`.

```cs
var shape = new Shape(0x000000);
var rectangle = new Rectangle(1, 2, 0xffffff);
var circle = new Circle((0, 0), 10, 0xffffff);

var shapeOp = new ShapeOperations();

shapeOp.ChangeColor(shape, 0x111111);
shapeOp.ChangeColor(rectangle, 0x111111);

// Ошибка! Circle не является наследником Shape
shapeOp.ChangeColor(circle, 0x111111);
```
