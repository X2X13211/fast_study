# Реализация интерфейса классом

---
dg-publish: true
---

Создадим класс `Point`, а для того чтобы представителей этого класса можно было сравнивать между собой на равенство, реализуем интерфейс `IEquatable<T>` . Изучив спецификацию интерфейса `IEquatable<T>` можно сделать вывод, что в `Point` нужно реализовать метод с сигнатурой `bool Equals(T? other)`, где вместо `T`, следует подставить тип `Point`. Напоминаем, что вопросительный знак после типа означает, что соответствующий параметр может принимать значение `null` . Таким образом, в реализации нам обязательно нужно будет добавить проверку на `null`.

```cs
class Point : IEquatable<Point>
{
    public double X { get; init; }
    public double Y { get; init; }

    // IEquatable<T>
    public bool Equals(Point? other)
    {
        if (other is null)
            return false;

        return X == other.X && Y == other.Y;
    }
}
```

Объекты типа `Point` будут считаться равными при равенстве значений полей `X` и `Y`.

Приведем несколько примеров работы с `Point`.

```cs
var p1 = new Point() { X = 1, Y = 2 };
var p2 = new Point() { X = 1, Y = 2 };
var p3 = new Point() { X = 3, Y = 4 };
Point? p4 = null;

Console.WriteLine(p1 == p2); // False
Console.WriteLine(p1.Equals(p2)); // True
Console.WriteLine(p1.Equals(p3)); // False
Console.WriteLine(p1.Equals(p4)); // False
```

Обратите внимание, оператор `==` при сравнении объектов выдает результат `false` . Это происходит из-за того, что он не переопределен в классе `Point` и использует реализацию по умолчанию, которая выполняет сравнение на тождество, а не на равенство. То есть в данном случае производится проверка того, что указывают ли `p1` и `p2` на один и тот же объект в памяти, без анализа их внутреннего содержимого.

Q: Для чего реализуется интерфейс `IEquatable<T>` в классе `Point`?
A: Для возможности сравнения объектов типа `Point` на равенство по их содержимому (значениям полей `X` и `Y`), а не по ссылке.

---

Q: Какую сигнатуру должен иметь метод `Equals`, реализуемый из интерфейса `IEquatable<Point>`?
A: `bool Equals(Point? other)`, где `Point?` указывает, что параметр может быть `null`.

---

Q: Почему в реализации метода `Equals` для `Point` необходима проверка `other is null`?
A: Чтобы избежать `NullReferenceException` при попытке доступа к свойствам `other.X` или `other.Y`, если `other` равен `null`.

---
Q: Какое значение вернёт `p1.Equals(p2)`, если `p1` и `p2` — объекты `Point` с одинаковыми `X` и `Y`?
A: `true`, так как метод `Equals` сравнивает значения полей, а не ссылки на объекты.

---
Q: Почему оператор `==` возвращает `false` при сравнении `p1 == p2`, даже если их поля `X` и `Y` равны?
A: Потому что оператор `==` по умолчанию сравнивает ссылки (тождество объектов), а не их содержимое, и не был переопределён в классе `Point`.

---
Q: Что выведет `p1.Equals(p4)`, если `p4 = null`?
A: `false`, так как в методе `Equals` есть явная проверка на `null`.

---
Q: Какие свойства класса `Point` используются для определения равенства двух объектов?
A: Свойства `X` и `Y` — объекты считаются равными, если оба свойства имеют одинаковые значения.

---
Q: Чем отличается поведение `Equals` от оператора `==` для объектов `Point` в приведённом примере?
A: `Equals` сравнивает содержимое объектов (значения `X` и `Y`), а `==` — их ссылки в памяти (тождество).
